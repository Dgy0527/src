# 目标站点开启了WAF或对高频扫描进行了封禁,如何获取敏感路径

# 1、高级搜索引擎语法
## 使用Google或Bing的高级语法搜索目录域名下的遗留路径
## 如 :`site:target.com intitle:"index of"`(查看目录列表)

# 2、网络空间搜索引擎
## 利用Fofa、Shodan、ZoomEye等平台,它们会定期扫描全网并存储历史数据;通过这些平台有时能直接看到目标服务器上曾经开放的端口、目录结构,甚至是一些已经被删除但依然存在于缓存中的敏感文件

# 3、JS爬取
## (1)手动或使用工具(如`web-Recon`)深度爬取目标网站的JavaScript文件
## (2)现代前端框架(如React、Vue)会将API接口、后台路径、隐藏参数硬编码在JS文件中

# 4、Github搜索
## 搜索目标公司员工的代码提交记录;有时候员工会将包含敏感路径的配置文件错误地提交到公开仓库

# 5、分析历史DNS记录
## 通过SecurityTrails等平台查询历史DNS解析记录;开发者有时会使用`dev.target.com`、`test.target.com`或`jenkins.target.com`作为内部测试子域名



# 原文
```
### 如果目标站点开启了 WAF 或对高频扫描进行了封禁，你会怎么获取敏感路径

**高级搜索引擎语法**：

- 使用Google或Bing的高级语法搜索目标域名下的遗留路径
- 例如：`site:target.com intitle:"index of"`（查看目录列表）

**网络空间搜索引擎**：

- 利用 Fofa、Shodan、ZoomEye 等平台。它们会定期扫描全网并存储历史数据。通过这些平台，我们有时能直接看到目标服务器上曾经开放的端口、目录结构，甚至是一些已经被删除但依然存在于缓存中的敏感文件

**JS 爬取**：

- 手动或使用工具（如`Web-Recon`）深度爬取目标网站的 JavaScript 文件
- 现代前端框架（如React、Vue）会将 API 接口、后台路径、隐藏参数硬编码在 JS 文件中

**GitHub 搜索**：

- 搜索目标公司员工的代码提交记录。有时候员工会将包含敏感路径的配置文件错误地提交到公开仓库

**分析历史DNS记录**：

- 通过SecurityTrails等平台查询历史DNS解析记录。很多时候，开发者会使用`dev.target.com`、`test.target.com`或`jenkins.target.com`作为内部测试子域名
```
